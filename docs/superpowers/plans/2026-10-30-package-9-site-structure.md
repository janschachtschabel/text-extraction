# Package 9: Site Structure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `POST /v1/site-structure {"url": "https://lernen.example.org/", "depth": 2}` answers 202 with a job that lists every sitemap of the site (robots.txt `Sitemap:` lines, sitemap indexes, gzip, text, RSS and Atom sitemaps) with all their URLs, and the site's link graph from the start page to the given depth: one item per page, each with its typed outgoing links (where on the page, which element, which `rel`) and the item index each followed link leads to.

**Architecture:**
- **A growing job on the extract pool (D1 a).** The route creates a job of kind `site` with one item, the start page. Every item is a page, the site's robots.txt, a sitemap file or a part of a large sitemap. A page item appends the pages it links to (one level deeper) and a sitemap item its child sitemaps, as new items of the same running job, in one Lua script per item (`site/store.py: SiteStore.extend`) that also deduplicates URLs, enforces `max_pages` and the file and URL caps, and is idempotent per parent. The new items go into the existing fair queue, so per-client and per-host fairness, leases, retries, deferrals on gate refusals and the paged `GET /v1/jobs/{id}` come for free. `total` grows while the crawl runs; the job completes when the last item is written, because a parent extends before it writes its own result.
- **Reuse for every fetch.** A page is `Pipeline.run` in fast mode with one new keyword (`site_links=True`): SSRF guard, compliance before and after the fetch and on each redirect hop, the host's `DomainGate` turn, `Crawl-delay`, the result cache, quality verdicts and DOM metadata all as for `/v1/extract`. Sitemaps go through a new `Pipeline.fetch_raw` (steps 2 to 6 of the pipeline, no conversion); robots.txt through the `ComplianceChecker`'s own cached load. The typed links come from a new pure module (`site/links.py`); `/v1/extract`'s `links` stays as it is.
- **Pure parsers, bounded.** Sitemaps parse with `defusedxml.ElementTree.iterparse` (no entities, no DTDs) after a bounded gzip inflate, on the worker's conversion pool; a sitemap larger than half of `JOB_ITEM_MAX_BYTES` is stored across finished `sitemap_part` items.

**Tech Stack:** existing only: httpx `Fetcher`, `DomainGate`, `ComplianceChecker` (protego's `sitemaps`), `FairQueue`, `JobStore`, Lua on Valkey, BeautifulSoup/lxml, `defusedxml` (already a base dependency), `zlib`. Tests: pytest, fakeredis, pytest-httpserver (sample sites), the real `Worker` in a thread as in package 8's done-when test.

**Spec:**
- `docs/packages.md` row 9: sitemap discovery (robots.txt, index, gzip), link graph with link types to a set depth, `POST /v1/site-structure` job. Done when sample sites return complete sitemaps and typed links.
- `docs/architecture.md`: the API row `POST /v1/site-structure` ("Sitemaps + typed link graph to a set depth", job), "Extraction pipeline" steps 1-3 (SSRF guard, compliance, per-domain outbound limits, `Crawl-delay`), "Result envelope and errors", "Jobs and the fair queue" (job keys, leases, `JOB_ITEM_MAX_BYTES`, `BATCH_MAX_OPEN_PER_CLIENT`, memory guard), "Outbound limits under load" (R21, R22, R25).
- `CLAUDE.md` rules 1, 2 (stateless pods, env vars with defaults, jobs over ~30 s), 4 (result envelope), 5 (SSRF guard on every fetch, byte and time limits), 6 (robots.txt and TDM checks, per-domain limits, honest user agent, no IP rotation), 7.

## Global Constraints

- English only. Python 3.13. No GPL or AGPL dependency; no new third-party package.
- Stateless pods: the crawl's state (nodes, seen URLs, children, counters) lives in Valkey under the job's hash tag `job:{<id>}:…` and expires with the job. No in-memory frontier.
- Every new setting is an env var with a documented default in `docs/configuration.md` and `.env.example`, and in the Helm chart's `config` map, in the task that adds it. No new secret.
- Every request a crawl sends goes through `Fetcher` (SSRF guard on the URL and on every redirect hop), inside the host's `DomainGate` turn, after the compliance checks of the job's mode (D4), with the service's own `USER_AGENT`. No browser (D3), no proxy, no rotation.
- Answers of the existing routes must not change apart from the new field `site: null`; cache keys of requests without `site_links` stay as they are (a deploy keeps the cache).
- Logs and metric labels carry hosts, roles, counts and outcomes only: never a full URL with its query, a link text or sitemap content (as "Query strings are never logged").
- `POST /v1/site-structure` always answers 202 with a job (or 4xx/503); it never crawls inline.
- Not in this package: browser rendering of crawl pages (D3), page content (D5), registrable-domain scope (D6), sitemap extensions (`image:`, `video:`, `news:`, `xhtml:link` alternates), an MCP tool (package 10).

## Decisions of Jan (2026-10-30: recommended options confirmed)

- **D1, how the crawl runs as a job.** (a, recommended) A growing job on the extract pool: every page, robots.txt and sitemap file is an item of the fair queue, discovered ones are appended to the running job, results are paged by `GET /v1/jobs/{id}`; per-host fairness, leases and retries per page come from package 3. (b) One item per crawl, run in a single worker slot with a lease heartbeat, the whole graph stored as one JSON artifact. (c) Like (a) but on a new `site` pool with its own worker deployment and Helm toggle.
- **D2, which link types.** (a, recommended) Rich: `kind` (`internal`, `external`, `file` as `/v1/extract` today), `source` (`a`, `area`, head `link`, `iframe`), `rel` tokens, `hreflang`, `region` (`nav`, `header`, `footer`, `aside`, `main`, `breadcrumb`, `pagination`) and the crawl decision per link. (b) Lean: `kind` and `rel` only. (c) Rich plus media (`img`, `video`, `audio` sources) as links.
- **D3, rendering of crawled pages.** (a, recommended) Fast mode only: links from the HTML as served; a JavaScript-only menu yields no links and the page's item says `js_heavy` in its quality. (b) `auto` per page: a page that needs a browser moves to the browser pool, and the browser worker appends its links. (c) A request option `mode` with both.
- **D4, compliance checks for the crawl.** (a, recommended) The same checks as an extraction for every fetch, sitemaps included: under `enforce` a page or sitemap that robots.txt disallows, or whose TDM rights are reserved, is not fetched (its link says `blocked`). (b) robots.txt only: TDM and `noai` govern content, which this route does not return. (c) robots.txt for pages; sitemaps are always fetched, since the site publishes them for crawlers.
- **D5, page content in the result.** (a, recommended) Structure only: a page item keeps title, status, metadata and quality, `content` is null; callers send the URLs they want to `POST /v1/batch`. (b) An option `content: true` keeps each page's text in its item. (c) Always keep the content.
- **D6, crawl scope.** (a, recommended) The start page's host (a leading `www.` ignored), and with `scope: "path"` only URLs under the start URL's directory. (b) The registrable domain with all subdomains (needs tldextract and the public suffix list in the base image). (c) (a) plus a caller list `hosts` of extra hosts to follow.

## Rulings in this plan

- **P9-S1, request and options** (`site/types.py`). `SiteStructureRequest` (extra forbidden): `url` (at most `MAX_URL_LENGTH`), `depth: int = 2` (0-10; over `SITE_MAX_DEPTH` 422), `max_pages: int = 100` (1-100,000; over `SITE_MAX_PAGES` 422; counts page items, the start page included), `sitemaps: bool = True`, `scope: Literal["host", "path"] = "host"`, `metadata: bool = True`, `compliance: ComplianceMode | None = None` (resolved by `resolve_mode`, `ignore` admins only), `cache: bool = True`. `depth: 0` fetches the start page only (plus sitemaps). `SiteOptions` (the same minus `url` and `compliance`) is stored as `JobOptions.site: SiteOptions | None = None`, omitted from the stored JSON while None (as `structured` in `_options_json`). `JobKind` gains `"site"`. Site items never reach another pool (fast, `ocr: never`, no `transcribe`, `pii`, `structured`, `chunking`), so `ExtractRequest(**job.options.model_dump())` is never built for them: `ExtractRunner.run` hands a `site` job to the `SiteRunner` first.
- **P9-S2, the result** (`site/types.py`). `ExtractResult.site: SiteInfo | None = None`. `SiteInfo`: `role: Literal["page", "robots", "sitemap", "sitemap_part"]`, `depth: int` (page: link distance from the start; sitemap: nesting, robots-listed = 0), `parent: int | None` (the item that found it), `links: list[SiteLink] | None`, `nofollow: bool = False` (the page said `nofollow`), `sitemaps: list[str] | None` (robots item: the sitemap URLs it listed or guessed), `sitemap: SitemapInfo | None`. `SiteLink`: `url`, `text` (whitespace collapsed, at most 200 characters), `kind: Literal["internal", "external", "file"]` (as `page_links`), `source: Literal["a", "area", "link", "iframe"]`, `rel: list[str]` (lower-case tokens, at most 8), `hreflang: str | None`, `region: Literal["nav", "header", "footer", "aside", "main", "breadcrumb", "pagination"] | None`, `crawl` (P9-S6), `target: int | None` (the item index of the linked page). `SitemapInfo`: `format: Literal["urlset", "index", "text", "rss", "atom", "absent"]`, `guessed: bool`, `entries: list[SitemapEntry]`, `children: list[SitemapChild]` (index only: `url`, `lastmod`, `crawl`, `target`), `entry_count: int` (the whole file's), `part: int` (1-based), `parts: int`. `SitemapEntry`: `loc`, `lastmod: str | None` (as given, at most 64 characters), `changefreq: Literal["always", "hourly", "daily", "weekly", "monthly", "yearly", "never"] | None`, `priority: float | None` (0-1, else None); its JSON leaves out null fields (a wrap `model_serializer`), so 5,000 entries stay near 500 KB. New warnings: `sitemap_not_found`, `sitemap_truncated`, `sitemap_urls_truncated`, `sitemap_files_truncated`, `links_truncated`, `max_pages_reached`, `site_memory_guard`.
- **P9-S3, the job's crawl keys** (`site/store.py`, all under the job's hash tag, TTL = the job meta's remaining TTL when written; `JobStore._KINDS` gains them so `delete` and `shorten` remove them):
  - `job:{<id>}:nodes` hash: index → `SiteNode` JSON (`role`, `depth`, `parent`, `guessed`, `part`).
  - `job:{<id>}:seen` hash: seen key (P9-S4) → index; sitemap files under `s:<key>`.
  - `job:{<id>}:children` hash: parent index → the stored answer of its `extend` (P9-S12).
  - `job:{<id>}:site` hash: `scope` (JSON `SiteScope`), `pages`, `files`, `entries`, `e:<index>` (entries granted to that sitemap item).
  - `SiteStore.init(job_id, url)` (by the route, right after `JobStore.create`): node 0 = page, depth 0, no parent; `seen[key(url)] = 0`; `pages = 1`.
  - `SiteStore.extend(...)` is one Lua script on `meta`, `urls`, `results`, `done`, `nodes`, `seen`, `children`, `site`: a repeat for the parent answers the stored answer and appends nothing; else for each candidate: a seen key answers its index; an `add` candidate under its cap (`pages < max_pages` for pages, `files < SITE_MAX_SITEMAP_FILES` for sitemaps) is appended (`RPUSH urls`, node, seen, counter, `total + 1`); otherwise nil with `capped` set. Finished items (`done`, sitemap parts) are appended with their result, done bit and the `done` and status counters, as `_STORE_RESULT` counts them. `aliases` (the page's `final_url` after a redirect) are added to `seen` pointing at the parent. The answer (indexes, the new `(index, url)` pairs, `capped`) is stored under the parent and returned.
  - `SiteStore.reserve_entries(job_id, index, wanted) -> int` grants up to `SITE_MAX_SITEMAP_URLS - entries`, idempotent per index (`e:<index>`).
- **P9-S4, URLs, keys and scope** (`site/urls.py`). `normalize_url(url) -> str | None`: absolute http(s) only, scheme and host lower case, default port dropped, fragment dropped, empty path `/`, query and percent-encoding unchanged, None when longer than `MAX_URL_LENGTH` or unparsable. `seen_key(url) -> str`: the normalized URL without its scheme and with a leading `www.` dropped from the host (http and https, with and without `www.`, are one page; the first URL seen is the item's). `SiteScope(host: str, path_prefix: str | None)`, set by item 0 from its `final_url` (else its URL): `host` without a leading `www.`; with `scope: "path"` `path_prefix` is the start path up to and including its last `/`. `in_scope(url, scope) -> bool`: same host ignoring `www.` (D6 a) and, with a prefix, a path that starts with it.
- **P9-S5, typed links** (`site/links.py`, pure). `site_links(html: str, base_url: str, headers: Mapping[str, str], *, max_links: int) -> PageLinks(links: list[SiteLink], nofollow: bool, truncated: bool)`. One BeautifulSoup parse (`convert.markup.parse_html`, `<base href>` via `base_url_of`). Elements in document order: `<a href>`, `<area href>`, head `<link href>` with a `rel` of `canonical`, `alternate`, `prev`, `next` (others skipped), `<iframe src>`. Same rules as `page_links`: http(s) only, fragment dropped, an in-page `#` link skipped, first occurrence per (URL, source) wins, `kind` by `has_file_extension` then host. `region` from the nearest ancestor, first match wins: `breadcrumb` (an `aria-label`, `class` or `id` containing `breadcrumb`, any case, or `itemtype` ending `BreadcrumbList`); `pagination` (`rel` `next`/`prev` on the link, or an ancestor `class`/`id` containing `pagination` or `pager`); `nav` (`<nav>`, `role="navigation"`); `header` (`<header>` outside `<article>`/`<main>`, `role="banner"`); `footer` (`<footer>` outside them, `role="contentinfo"`); `aside` (`<aside>`, `role="complementary"`); `main` (`<main>`, `<article>`, `role="main"`); else None. `nofollow` when `<meta name="robots">` or `<meta name="text-extraction">` or the `X-Robots-Tag` header (unnamed or for `text-extraction`) says `nofollow` or `none`. Over `max_links` (`SITE_MAX_LINKS_PER_PAGE`) the first ones, `truncated`.
- **P9-S6, follow rules** (`site/follow.py`, pure but for the cached compliance judgement). `crawl` per link: `listed` (source `link` or `iframe`: never followed), `file`, `out_of_scope`, `nofollow` (its `rel` has `nofollow` or the page said `nofollow`), `blocked` (`Pipeline.blocked_from_cache` is true for the job's mode; None, not cached, means follow and let the item decide), `depth` (the child would be deeper than `depth`; still looked up, so a seen page gets its `target` and `seen`), then `extend` decides `queued` (new item), `seen` (an existing item) or `max_pages` (cap reached; `memory_guard` while the guard is high, when nothing is appended). A page's candidates are unique by seen key, in link order (the queue is FIFO per host, so the crawl is breadth-first in practice and `max_pages` keeps the first found).
- **P9-S7, sitemap discovery.** Item 0, whatever its outcome, appends the robots item (`role: robots`, URL `<origin>/robots.txt` of its `final_url`, else of its URL) when `sitemaps` is asked, before its links. The robots item reads robots.txt through `Pipeline.robots_sitemaps` (the checker's cached entry, else loaded in the host's turn; also under `compliance: ignore`, since reading robots.txt checks nothing): `found` with `Sitemap:` lines → those URLs (at most `SITE_MAX_SITEMAP_FILES`) as `sitemap` items, depth 0, any host; `found` without them or `absent` → one guess `<origin>/sitemap.xml` (`guessed: true`); `unavailable` → `failed`/`target_http_error`, retryable, "robots.txt could not be retrieved.", no guess. Its result is `success` with `site.sitemaps` the URLs it appended.
- **P9-S8, sitemap parsing** (`site/sitemaps.py`, pure; runs on the worker's `ConversionPool`). `inflate_bounded(body, max_bytes) -> tuple[bytes, bool]` when the body starts with `\x1f\x8b` (any name or type; the fetcher already inflates `Content-Encoding`), `zlib.decompressobj(16 + zlib.MAX_WBITS)` with `max_length` steps, cut at `max_bytes`. `parse_sitemap(body, base_url, *, max_entries) -> ParsedSitemap(format, entries, children, entry_count, truncated, error)`: a body whose first non-whitespace byte (after a BOM) is not `<` is `text` (one URL per line, UTF-8, lines that `normalize_url` refuses skipped); otherwise `defusedxml.ElementTree.iterparse(forbid_dtd=True, forbid_entities=True, forbid_external=True)`, elements cleared as they close, namespaces ignored by local name: root `urlset` (`url/loc`, `lastmod`, `changefreq`, `priority`), `sitemapindex` (`sitemap/loc`, `lastmod`), `rss` (`item/link`, `pubDate` as `lastmod`), `feed` (`entry/link[@href]`, `updated`); any other root is `error: "unsupported"`; a parse error after some entries keeps them with `truncated`, before any is `error: "invalid"`. `loc`s are resolved against `base_url` and normalized; others are dropped. At most `max_entries` entries (`truncated`), `entry_count` counts all valid ones.
- **P9-S9, sitemap parts.** `pack_parts(entries, max_bytes) -> list[list[SitemapEntry]]` greedily by each entry's JSON length, `max_bytes = JOB_ITEM_MAX_BYTES // 2`; part 1 is the sitemap item's own result, parts 2..k are finished `sitemap_part` items (same URL, `parent` the sitemap item, `part` i of `parts` k) appended by the same `extend` call as the index's children.
- **P9-S10, pipeline hooks** (`pipeline.py`, `compliance.py`).
  - `Pipeline.run(..., site_links: bool = False)`: `_Run.site_links`; `_process` computes `site_links(text, final_url, fetched.headers, max_links=SITE_MAX_LINKS_PER_PAGE)` for HTML (`[]` for text, None for documents and media) into `ExtractResult.site = SiteInfo(role="page", depth=0, parent=None, links=..., nofollow=...)`, with `links_truncated`; `_cache_options` adds `"site_links": true` only when set.
  - `Pipeline.fetch_raw(url, principal, compliance, *, max_bytes, truncate, gate_refusals) -> RawFetch` runs steps 2 (validate), 4 (compliance before the fetch, in the host's turn when not cached), 5 (`_fetch`: redirect hops checked, outcome recorded) and `after_fetch` on the headers (`html=None`); `RawFetch(fetched: FetchResult | None, report: ComplianceReport, failure: Envelope[ExtractResult] | None, attempts: int, timings: Timings)`; `failure` for a block (`blocked_by_robots`, `tdm_reserved`) or a `FetchError`; any HTTP status is returned as `fetched`. Same deadline (`EXTRACT_TIMEOUT_SECONDS`) and gate refusals as `run`.
  - `ComplianceChecker.robots_sitemaps(url, *, cached_only: bool) -> RobotsSitemaps | None` (`state: Literal["found", "absent", "unavailable"]`, `urls: list[str]` from protego's `sitemaps`, http(s) and normalized); `cached_only` answers None when the entry is not cached. `Pipeline.robots_sitemaps(url, *, gate_refusals) -> RobotsSitemaps` asks the cache first, else takes the host's turn and loads the file (`_load`, the 10 s budget).
  - `Pipeline.blocked_from_cache(url, mode) -> bool | None`: `cached_before_fetch`, then `blocking_code(report) is not None`; None when not cached.
- **P9-S11, the runner** (`site/runner.py`). `SiteRunner.run(job, item, url, *, gate_refusals) -> Envelope[ExtractResult]` reads `SiteStore.context(job_id, index)` (node and scope; no node: `failed`/`internal_error`, not retryable) and runs the role:
  - `page`: `Pipeline.run(ExtractRequest(url=url, mode="fast", format="text", metadata=opts.metadata, links=False, compliance=job.options.compliance, cache=opts.cache, ocr="never"), principal, gate_refusals=..., site_links=True)`; item 0 sets the scope and appends the robots item (P9-S7); the links of any result with `site.links` (success, partial, or failed by a quality verdict) are judged (P9-S6), `extend`ed with the `final_url` as alias, the new items enqueued (`FairQueue.enqueue_items(job.id, item.client, ...)`), then the answer: `content` null (D5 a), `links` null, `site` with depth, parent, links (`crawl`, `target` set), `max_pages_reached` or `site_memory_guard` when it applied.
  - `robots`: P9-S7.
  - `sitemap`: `fetch_raw(url, max_bytes=SITE_SITEMAP_MAX_BYTES, truncate=True)`; a failure is its envelope with `site`; 404 or 410 of a guessed sitemap is `success`, `format: absent`, `sitemap_not_found`; any other non-2xx is `failed`/`target_http_error`; then inflate, `reserve_entries`, parse (`max_entries` = granted), parts, children (`add` when depth + 1 ≤ 3 and on the index's host or the scope host, else `crawl: depth` or `out_of_scope`), `extend`, enqueue. `error: "invalid"` is `failed`/`conversion_failed` ("The sitemap could not be read."), `"unsupported"` `failed`/`unsupported_content_type`; a cut body, an inflate cut or a cut by `max_entries` is `partial` with `sitemap_truncated` or `sitemap_urls_truncated` (`error.code` `too_large`, not retryable).
  - Results of `robots` and `sitemap` items are built by `site_result(...)` (P9-S11 helper: `mode_used: fast`, `format: text`, `content` null, `word_count` 0, the report, timings, attempts).
- **P9-S12, reruns and failures.** A parent whose lease was lost runs again: `extend` answers its stored answer (no duplicate items) and the runner enqueues those new items again (a duplicate queue entry is skipped by `has_result`). An exhausted item of a `site` job first re-enqueues its stored children (`SiteRunner.requeue_children`), then fails `internal_error` as today, so the job still completes. While the memory guard is high, `extend` gets no `add` candidates (lookups only) and the page answers `site_memory_guard`. A gate refusal propagates as for batch items (deferral); a Valkey error backs off.
- **P9-S13, the route** (`site_api.py`). `POST /v1/site-structure` (user role): 503 while jobs are off (`require_jobs_enabled`), `validate_url` (422 `invalid_request` for a bad URL), `depth` and `max_pages` against the settings (422), `resolve_mode` (403), memory guard (503), `BATCH_MAX_OPEN_PER_CLIENT` shared with batches (429) through `jobs_api.open_job(request, principal, kind, options, urls) -> str` (the shared part of `create_batch`, moved out unchanged), `SiteStore.init`, enqueue item 0 for the client `principal.name`; 202 `JobAccepted(kind="site", total=1, status_url=...)`. Body limit `REQUEST_MAX_BODY_BYTES`. OpenAPI: summary, description, an example body.
- **P9-S14, settings.** `SITE_MAX_DEPTH` (5, 0-10), `SITE_MAX_PAGES` (1,000, 1-100,000), `SITE_MAX_SITEMAP_FILES` (500, 1-50,000), `SITE_MAX_SITEMAP_URLS` (200,000, 1-5,000,000), `SITE_SITEMAP_MAX_BYTES` (52,428,800, the protocol's 50 MiB; 1,024-209,715,200; the fetch cap and the inflate cap of one file), `SITE_MAX_LINKS_PER_PAGE` (1,000, 10-50,000). Helm `config` gets all six with these values.
- **P9-S15, metrics and logs.** `text_extraction_site_items_total{role, outcome}`, `text_extraction_site_links_total{crawl}`, `text_extraction_site_caps_total{cap="pages"|"files"|"urls"|"links"|"memory"}`. ## Review Focus

1. **Crawler traps:** a calendar page linking `?month=n+1` forever, session ids in every link, `/a/./b/../b`, a redirect loop A→B→A, two pages that link each other. The job completes; at most `max_pages` page items; a page appears once. Owner: Task 6 (`test_calendar_trap_stops_at_max_pages`, `test_cycle_and_alias_are_one_item`).
2. **Hostile sitemaps:** a gzip bomb (1 GB of zeros, 1 MB compressed), a billion-laughs DTD, an external entity, an index that lists itself, an HTML error page answered 200 as `sitemap.xml`, 60,000 entries. Memory stays bounded by `SITE_SITEMAP_MAX_BYTES`, entities are refused (`conversion_failed`), the self-reference is `seen`, HTML is `unsupported_content_type`, 60,000 entries arrive complete across parts. Owner: Tasks 2 and 6 (`test_gzip_bomb_cut_at_limit`, `test_entities_refused`, `test_self_listing_index_is_seen`, `test_sixty_thousand_entries_across_parts`).
3. **SSRF through the site:** a `Sitemap: http://169.254.169.254/latest` line, an index child `http://127.0.0.1:6379/`, a link that redirects to a private address. Never fetched; the item is `failed`/`blocked_url`; the crawl goes on. Owner: Task 6 (`test_private_sitemap_and_redirect_blocked`, with `FETCH_ALLOW_PRIVATE_NETWORKS=false` and a guarded resolver stub).
4. **Lost leases mid-crawl:** a worker killed after `extend` and before `enqueue`, a parent that runs twice, an exhausted parent. No item twice, every child queued, the job completes. Owner: Tasks 4 and 6 (`test_extend_repeat_returns_stored_answer`, `test_rerun_parent_requeues_children`, `test_exhausted_parent_requeues_children_and_job_completes`).
5. **Huge pages:** 50,000 links, a link text of 1 MB, a 10,000-character `href`, 3,000 iframes. At most `SITE_MAX_LINKS_PER_PAGE` links with `links_truncated`, texts cut at 200, long URLs dropped, the item's JSON under `JOB_ITEM_MAX_BYTES`. Owner: Task 3 (`test_link_caps_and_cuts`) and Task 6 (`test_page_item_stays_under_item_limit`).
